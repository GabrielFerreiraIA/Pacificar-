## Decisões tomadas
- Cron interno é a terceira camada, não substitui Vercel/GitHub: escrita interna pode não contar como atividade, por isso a chamada HTTP pelo gateway.
- Intervalo de 6h: 4 linhas/dia, irrelevante para o limite do plano grátis.

## Como testar
1. SQL Editor: `select * from cron.job;` mostra `pacificar-keepalive` ativo.
2. Depois de 6h: `select source, created_at from heartbeat order by created_at desc limit 5;` com linhas `supabase-cron`.
3. `select status_code from net._http_response order by created desc limit 5;` com 200.
4. Teste feito nesta sessão: execução manual gravou a linha, HTTP 200 `{"ok": true, "total": 1}`. `supabase/tests/rls_test.sql` → RLS OK. Paciente alterando `eduzz_invoice_id` é bloqueada.
